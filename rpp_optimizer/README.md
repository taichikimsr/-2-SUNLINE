# 楽天RPP 自動運用ツール

RMSからダウンロードしたRPPレポートを入れるだけで、次の作業を自動で行うStreamlitアプリです。

1. 商品ごとの採算診断（損益分岐ROAS・必要CVR・分類）
2. 登録済みキーワードのCPC変更・削除
3. 新規キーワードの発見と、テスト用CPCでの追加
4. 商品CPC（キーワード以外の配信）の調整と、除外候補の抽出
5. RMS一括アップロード用CSV（キーワード・商品）と、次回の効果検証に使う運用記録の出力

## 起動

```bash
pip install -r rpp_optimizer/requirements.txt
streamlit run rpp_optimizer/app.py          # Windows: py -m streamlit run app.py
```

`sample_data/rms_*.csv` と `search_keywords_sample.csv` は架空の数値のサンプルです。

## 毎週の運用

| 手順 | 内容 |
|---|---|
| 1 | RMS → RPP → パフォーマンスレポートで、直近30日（大型セール期間は避ける）の「キーワード別」「商品別」をCSVでダウンロード |
| 2 | ツールにまとめて入れる。前回の「運用記録CSV」も一緒に入れると、前回の施策の効果を検証し、下げすぎたキーワードを自動で戻す |
| 3 | 「アクションプラン」を確認（チェックを外した行は出力しない／CPCは編集可） |
| 4 | 「出力」のCSVを、RMSの「キーワードCPCの登録/更新」「商品CPCの登録/更新」からそのままアップロード |
| 5 | 運用記録CSVを保存（次回使用） |

## 判断のロジック

### 目標ROAS
- 損益分岐ROAS ＝ 100 ÷ 粗利率（粗利率30% → 333%）
- 目標ROAS ＝ 損益分岐ROAS × モード係数（利益重視1.3／バランス1.1／売上拡大0.9）
- 商品マスタCSV（商品管理番号・粗利率・目標ROAS）で商品ごとに指定可能

### 1クリックあたりの売上（補正あり）
クリックの少ない商品・キーワードは、上位の平均（キーワード→その商品、商品→店舗全体）に寄せて補正します。
目標CPC ＝ 補正後の1クリック売上 ÷ 目標ROAS。

「既存顧客の売上の評価」を1未満にすると、既存顧客の売上を割り引いて評価します。
既存顧客は広告が無くても購入した可能性があるためで、新規顧客の獲得に強い入札になります。

### 商品の分類
| 分類 | 条件 | 対応 |
|---|---|---|
| 構造的赤字 | 目標CPCがキーワード下限の3/4未満、かつ見込みROASが目標の8割未満 | 広告費を絞り、ページ改善を指示。必要CVRを提示。新規キーワードは追加しない |
| 拡大 | 見込みROASが目標の1.2倍以上 | 入札を上げ、露出を拡大 |
| 維持／調整 | それ以外 | 目標CPCに向けて調整 |
| データ不足 | クリック30回未満 | 様子見（新規キーワードのテストは可） |

### 登録済みキーワード
- 受注0件で、粗利1件分（客単価×粗利率）以上を使った → **削除（d）**
- 見込みROASが目標の半分未満 → 最大−50%まで大きく下げる
- 下限CPCでも採算が合わない → 受注0なら削除、受注ありなら削除候補（手動判断）
- 好調で、楽天の目安CPCより低い → 目安CPCまで早めに引き上げて露出を取る
- 前回下げた結果、1日あたりクリックが半分未満になり、ROASは目標以上 → 一部戻す
- セール期間モード → 好調なキーワードを上乗せ（次回の通常運用で戻る）

### 新規キーワード
RPPのレポートには登録済みのキーワードしか載らないため、次の3つの材料から候補を作ります。

1. **検索キーワードデータ**（RMSのアクセス分析などから出力した、実際に流入があった語）：最優先
2. **他商品で受注した語の横展開**（その語を商品名に含む商品へ）
3. **商品名の語の組み合わせ**
   - 「ブランド＋固有の語」「固有の語＋カテゴリー語」の2語の組み合わせを作る
   - 1語だけの広い語は作らない
   - 宣伝文句（送料無料・プレゼント等）は除外する

候補ごとに想定1クリック売上からテスト用CPCを計算し、キーワード下限（40円）に届かない（＝赤字になる）ものは追加しません。
売上拡大モードの場合だけ、下限CPCで追加します。
同じ語ばかりにならないよう分散して選び、1商品あたりの登録上限（初期値20）を超えないようにします。
追加したキーワードは次回のレポートで成果を見て、継続・調整・削除を自動で判断します。

### 商品CPC
商品別とキーワード別の両方があれば、「商品全体 − キーワード経由」を、キーワード以外の配信（商品CPCで配信される部分）として評価し、商品CPCを調整します。
下限でも目標の半分未満なら、除外候補にします。

## 確認済みの仕様と未確認の点

| 項目 | 状態 |
|---|---|
| キーワードCPCの一括アップロード形式（4列・Shift_JIS・LF改行） | RMSのサンプルCSVで確認済み |
| コントロールカラム n（新規）／d（削除） | サンプルCSVで確認済み |
| コントロールカラム u（変更） | 解説記事の情報。登録済みキーワードに n を送ると「既に登録済」エラーになることは確認済み |
| 商品CPCの一括アップロード形式 | **未確認**（商品別レポートの列名に合わせて出力） |
| 商品別レポートの列構成 | **未確認**（キーワード別レポートから推定） |
| キーワード下限40円・商品下限20円・1商品20キーワード | 解説記事の情報。設定で変更可 |
| RPPの入札を変更する公開API | 確認できず。このため反映はCSVの一括アップロードで行う |

## ファイル構成

```
rpp_optimizer/
├── app.py              # 画面
├── rpp/
│   ├── io.py           # CSV読み込み（文字コード・説明行・列名・種類・集計期間の自動判定）
│   ├── datasets.py     # 種類ごとの整形
│   ├── strategy.py     # 自動運用エンジン（診断・入札・新規キーワード・商品CPC・運用記録）
│   ├── keywords.py     # キーワードの正規化・商品名からの候補生成
│   ├── bidding.py      # レポートの集計（旧版の入札ロジックも含む）
│   └── export.py       # 一括アップロード用CSV
├── sample_data/        # 架空のサンプル
└── tests/              # python -m pytest rpp_optimizer/tests
```

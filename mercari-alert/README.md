# メルカリお得品アラート

メルカリに出品されている時計・高級品などを毎日自動でチェックし、
**中古相場より一定以上安い出品**が見つかったら Discord に通知するシステムです。
GitHub Actions 上で毎日決まった時刻に自動実行されます（PC の起動は不要）。

## 仕組み

1. `config.yaml` の監視条件（検索語・価格帯・状態）ごとに、メルカリを新着順で検索
   - 出品中の商品：最新 最大120件
   - 売り切れの商品：最新 最大120件（相場の算出用）
2. 商品名に「箱のみ」「ベルトのみ」「レプリカ」などを含む出品、価格帯・状態の条件外の出品を除外
3. 相場を決める
   - `reference_price`（自分で調べた相場）を設定していれば、それを相場とする
   - 未設定なら、売り切れ商品の価格の**中央値**を相場とする（最低5件必要。件数は設定で変更可）
4. 出品中の商品のうち、相場より `discount_threshold`（初期値 25%）以上安いものを Discord に通知
   - 相場の35%未満など**安すぎるもの**には「偽物・付属品のみ・誤記の可能性」の警告を付けます
   - 一度通知した商品は再通知しません。ただし**値下げされた場合は再通知**します
5. 実行ごとに「チェック完了」のまとめ（各監視の相場・件数）と、エラーがあればその内容も通知します

## セットアップ手順

### 1. Discord の Webhook URL を作る
1. 通知を受け取りたい Discord サーバーのチャンネルで「チャンネルの編集（歯車）」を開く
2. 「連携サービス」→「ウェブフック」→「新しいウェブフック」
3. 「ウェブフックURLをコピー」

### 2. GitHub に Webhook URL を登録する
1. このリポジトリの **Settings → Secrets and variables → Actions**
2. **New repository secret** で以下を登録
   - Name: `DISCORD_WEBHOOK_URL`
   - Secret: 手順1でコピーした URL

### 3. デフォルトブランチ（main）に取り込む
GitHub Actions の定期実行（schedule）は**デフォルトブランチにあるワークフローしか動きません**。
このブランチの内容を main にマージしてください。

### 4. 動作確認
1. リポジトリの **Actions** タブ →「メルカリお得品アラート」→ **Run workflow** で手動実行
2. Discord に「チェック完了」のメッセージが届けば成功です
3. 以後は毎日 日本時間 8:17 頃に自動実行されます（時刻・回数は `.github/workflows/mercari-alert.yml` の `cron` で変更。UTC 指定なので日本時間から9時間引いた値を書きます）

### 5. 監視する商品を設定する
`config.yaml` の `watches` を編集します。同梱の3件は**書き方の例**で、金額は実際の相場ではありません。

```yaml
watches:
  - name: ロレックス サブマリーナ 116610LN   # 通知に表示する名前
    keyword: ロレックス サブマリーナ 116610LN # メルカリの検索語（型番まで入れると精度が上がる）
    price_min: 300000                        # これ未満は付属品等とみなして除外
    condition_ids: [1, 2, 3, 4]              # 状態「傷や汚れあり」以下を除外
    reference_price: 1200000                 # 任意：自分で調べた相場（円）※この金額は記入例
    discount_threshold: 0.2                  # 任意：この監視だけ20%以上安ければ通知
```

**精度を上げるコツ**
- 検索語は「ブランド＋モデル名＋型番」まで具体的にする（例：「ロレックス」単体だと相場がぶれて判定が意味を成しません）
- `price_min` を本体として現実的にあり得ない価格より少し上に設定し、ベルト・箱などを除外する
- 相場がはっきりしている商品は `reference_price` に自分で調べた中古相場（買取店・中古専門店の実売価格など）を入れる

全項目の説明は `config.yaml` 内のコメントにあります。

## 手元の PC で実行する場合

```bash
cd mercari-alert
pip install -r requirements.txt

# 通知せず結果をログに表示（記録も更新しない）
python -m mercari_alert.main --dry-run

# Discord にテスト通知を送る
export DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/..."
python -m mercari_alert.main --test-notify

# 通常実行
python -m mercari_alert.main
```

テスト: `python -m pytest`（メルカリへの通信は行わず、応答を模擬して検証します）

## ファイル構成

```
.github/workflows/mercari-alert.yml   毎日の自動実行（GitHub Actions）
mercari-alert/
├── config.yaml                      監視条件・判定設定
├── mercari_alert/
│   ├── client.py                    メルカリ検索（非公式API）
│   ├── analyzer.py                  除外・相場算出・お得判定
│   ├── notifier.py                  Discord 通知
│   ├── state.py                     通知済み記録
│   └── main.py                      実行処理
├── state/seen.json                  通知済み商品の記録（自動更新・60日で削除）
└── tests/test_alert.py              テスト
```

## 注意事項（必ずお読みください）

- **利用規約上のリスク**：メルカリは一般向けの検索APIを公開しておらず、本システムはメルカリのWebサイトが内部で使っているAPIを利用します。
  - 2025年11月25日に確認した利用規約（2025年10月22日改定版）と、第8条が参照するガイド「禁止されている行為」には、スクレイピングや自動アクセスを名指しで禁止する文言は見当たりませんでした。
  - ただし、ガイドには「その他、不適切と判断される行為」という包括的な禁止項目があります。また規約第5条では、メルカリが「相応しくないと判断した場合」に、事前通知なくアクセスを拒否できるとされています。許可されているわけではありません。
  - 本システムはログイン不要のため、アカウントとは紐付きません。1日1回・少数の検索・リクエスト間隔4〜8秒という低頻度で動作しますが、アクセス拒否などのリスクはあります。ご自身の判断と責任でご利用ください。
  - 規約は変更されることがあります。最新版は https://static.jp.mercari.com/tos と https://help.jp.mercari.com/guide/articles/258/ でご確認ください。
- **動作未確認の部分**：開発時には**実際のメルカリAPIに対する動作テストを行っていません**（テストは応答を模擬したもの）。初回は手動実行でログと Discord のまとめ通知を確認してください。
- **API仕様の変更**：非公式APIのため、メルカリ側の変更で突然動かなくなる可能性があります。その場合は Discord にエラー通知が届きます。
- **GitHub Actions からのアクセス拒否**：GitHub Actions は海外のクラウドサーバーから実行されるため、メルカリ側にブロックされる（HTTP 403 など）可能性があります。その場合は手元の PC やサーバーで cron／タスクスケジューラを使って実行してください。
- **相場の限界**：売り切れ商品は「出品が新しい順」で取得しており、「売れた日」の新しい順ではありません。また、同じ検索語でも型番違い・状態違いの商品が混ざると中央値がずれます。相場が重要な商品は `reference_price` の設定を推奨します。
- **偽物・状態の確認**：通知は価格だけで判定しています。購入前に写真・説明文・出品者の評価を必ずご自身で確認してください。
- **定期実行の遅延・停止**：GitHub Actions の定期実行は混雑時に数分〜数十分遅れることがあります。また、公開リポジトリでは60日間リポジトリに活動がないと定期実行が自動で無効になります（GitHub の仕様）。
- **通知のタイミング**：1日1回のチェックのため、人気商品は通知前に売れてしまうことがあります。回数を増やす場合も、メルカリへの負荷を考慮し数時間おき程度にとどめてください。

# 楽天RPP広告 CPC最適化ツール

RMSからダウンロードしたRPP広告のレポートCSVをもとに、**商品ごと・キーワードごとの推奨CPC**を計算し、
RMSへ一括アップロードするためのCSVを出力するStreamlitアプリです。

## 前提（2026年11月時点で確認できた範囲）

- 楽天の公開API（Rakuten Web Service / RMS WEB SERVICE）には、RPPの入札（CPC）を変更・取得するAPIは確認できませんでした。
  このため本ツールは **RMSへの自動反映は行わず**、「レポートCSVの取り込み → 推奨値の計算 → アップロード用CSVの出力」までを行います。
- 下限CPCは、各種解説記事で「商品CPC 20円（2025年の仕様変更で10円から引き上げ）／キーワードCPC 40円」とされていますが、
  楽天の公式資料では未確認です。初期値として設定していますが、**RMSの画面で最新の値を確認し、サイドバーで変更してください。**
- 一括アップロードCSVの正確な列構成は、RMSのRPP「商品・キーワード設定」でダウンロードできるサンプルフォーマットで確認してください。
  そのCSVをアプリの「テンプレート」欄に読み込むと、**その列構成のままCPCの列だけを書き換えて**出力します。

## 起動

```bash
pip install -r rpp_optimizer/requirements.txt
streamlit run rpp_optimizer/app.py
```

`sample_data/` に架空の数値のサンプルCSVがあります。動作確認に使えます。

## 推奨CPCの計算方法

| 手順 | 内容 |
|---|---|
| 1 | 1クリックあたり売上（VPC）＝ 売上金額 ÷ クリック数 |
| 2 | クリック数が少ないものは平均値に寄せて補正（ベイズ平滑化）<br>補正後VPC ＝（売上金額 ＋ 平均VPC × 仮想クリック数）÷（クリック数 ＋ 仮想クリック数）<br>平均VPCは、キーワードなら同じ商品全体、商品なら店舗全体 |
| 3 | 理論上限CPC ＝ 補正後VPC ÷ 目標ROAS |
| 4 | 現在CPCから±一定割合（初期値20%）以内に制限し、下限〜上限CPCの範囲に収めて1円単位に丸める |

### 判定区分

| 判定 | 条件 |
|---|---|
| 引き上げ / 引き下げ | 理論上限CPCと現在CPCの差が「据え置き幅」（初期値±5%）を超える |
| 据え置き | 差が据え置き幅以内、または上限・下限に達していて動かせない |
| データ不足（据え置き） | クリック数が最低クリック数（初期値30）未満 |
| 引き下げ（売上0） | 売上0円のまま広告費が基準額（初期値3,000円）以上 |
| 要確認（停止・除外を検討） | 下限CPCまで下げてもROASが目標の半分未満の見込み。キーワードは削除、商品は除外商品への登録を検討 |

### 目標ROASの決め方（優先順）

1. 商品マスタの「目標ROAS」列（商品ごとの個別目標）
2. 「粗利率から自動算出」がオンの場合：損益分岐ROAS（100 ÷ 粗利率）× 係数
   - 例：粗利率25% → 損益分岐ROAS 400% → 係数1.2で目標480%
3. サイドバーの目標ROAS（全商品共通）

## 運用の目安

- 調整は週1回程度、集計期間は直近14〜30日を推奨します。変更直後は数値が安定しないため、毎日の変更は避けてください。
- 「分析結果CSV」を毎回保存しておくと、変更前後の比較に使えます。
- 売上金額は「12時間」「720時間」の計測期間を選べます。リピート購入や検討期間の長い商品は720時間の方が実態に近くなります。

## ファイル構成

```
rpp_optimizer/
├── app.py              # Streamlit画面
├── rpp/
│   ├── io.py           # CSV読み込み（文字コード・ヘッダー行・列名の自動判定）
│   ├── bidding.py      # 推奨CPCの計算
│   └── export.py       # 一括アップロード用CSVの作成
├── sample_data/        # 架空の数値のサンプルCSV
├── tests/              # 単体テスト（python -m pytest rpp_optimizer/tests）
└── requirements.txt
```
